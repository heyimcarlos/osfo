# Complete a Research Report

Research Report is a governed Plan-neutral Agent capability that gathers bounded public evidence and publishes one cited immutable report artifact. The retained launch-v1 policy still requires an active Adventurer subscription for Workflow admission, so local verification proves that subscription through the billing authority before starting the report.

## Sub-features

- ordinary start without Approval;
- one stable Workflow identity exposed by the Agent;
- status inspection through the Agent control;
- dedicated Cloudflare Workflow execution;
- deterministic local discovery, page retrieval, and cited synthesis provider operations;
- immutable source manifest, synthesis evidence, and report artifact in R2;
- launch-v1 Workflow-start and useful-report accounting;
- terminal product truth before the exactly-once Agent follow-up;
- permanent deletion of every private report, provider-operation, notification, source, synthesis, and artifact obligation.

## How to get to it (user POV)

After registration, complete the local Stripe verification Checkout, reconcile an active Adventurer subscription, and make the single Telegram linking attempt. Then send the linked Agent: `Research durable Workflow verification using public sources and create a cited PDF report.`

## Driving it with Chrome

1. Complete [registration](registration.md) in Chrome, open `/settings/billing`, start the real Osfo Checkout, choose `Complete verification checkout` on the loopback Stripe page, and wait for `/settings/billing` to show `Adventurer Plan`. This completion returns through Osfo's production billing reconciliation service; it is not a database mint.
2. Complete [channel linking](channel-linking.md) in the same Chrome tab. Do not request a second Telegram invitation.
3. Start Research Report evidence. Capture the browser's committed `Channel linked` state as `action.png`, then run `control-osfo telegram-reply <run-id> "Research durable Workflow verification using public sources and create a cited PDF report."` once. The helper delivers the message through the real Telegram webhook and linked Agent; it does not call a Research Report service or mutate product state.
4. Wait for the Agent reply to contain the stable Research Report Workflow identity. Do not infer success from this acknowledgement.
5. Run `control-osfo telegram-reply <run-id> "Inspect Research Report <workflow-id> status."` Wait for the linked Agent to report `success`, the artifact identity, and no safe failure code. Open the authenticated dashboard notification center and capture the safe terminal Research Report update as `result.png`.
6. Record both screenshots, run `observe research-report`, and finish the evidence.
7. Continue to [account deletion](account-deletion.md). Its observer must confirm that the Research Report graph and R2 objects are gone along with the User.

PASS requires one successful report within 60 minutes; one search and one fetched-page operation with no fetched body in PostgreSQL; one deterministic cited synthesis operation; matching immutable source-manifest, synthesis, and artifact objects in R2; one launch-v1 Workflow-start and one useful Research Report accounting fact; terminal product truth before one delivered terminal notification; and exactly one discovery, page, and synthesis call in the local Research provider ledger.

## Gotchas

- `RESEARCH_REPORT_PROVIDER_BASE_URL` is accepted only for a loopback origin in test or development. Preview and production keep Cloudflare discovery and synthesis fail-closed until their price and activation evidence are recognized.
- The local provider uses a canonical public HTTPS source identity while transporting deterministic bytes over the isolated loopback emulator. It does not relax the production public-URL policy.
- The Agent acknowledgement proves admission, not completion. Require the later Agent inspection and the committed observer.
- The terminal follow-up contains only safe committed status. It is not report-content delivery.
- Do not bypass launch-v1 by updating billing rows. The loopback hosted Checkout and authenticated return reconciliation are the local proof of Adventurer authority.
